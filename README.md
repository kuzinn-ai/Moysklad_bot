# Paradise Telegram Bot and Mini App

Telegram-бот и Mini App для просмотра остатков, подготовки черновика закупки и ведения заказов покупателей. Mini App и бот запускаются одним процессом: бот получает обновления Telegram, а встроенный веб-сервер обслуживает страницу и её API.

## Настройки

Задайте переменные окружения. Для PyCharm их можно указать в Run Configuration; для Docker — в защищённом environment settings хостинга или в локальном `.env`:

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота от BotFather |
| `MOYSKLAD_TOKEN` | Токен API МоегоСклада |
| `TELEGRAM_USER_IDS` | Разрешённые Telegram ID через запятую |
| `MINIAPP_URL` | Публичный HTTPS-адрес Mini App; без него бот не показывает кнопку открытия |
| `PORT` | Порт веб-сервера; на хостинге обычно задаётся платформой |
| `CUSTOMER_ORDERS_DB` | Путь к SQLite-файлу заказов; на сервере укажите путь на постоянном диске |
| `MINIAPP_LOCAL_DEV` | Только для локальной разработки; на сервере не задавать |

Не добавляйте реальные секреты в Git, URL, исходники или `.env.example`. Файл `main/config.py` подходит только для локальной разработки и исключён из Git и Docker-сборки.

## Локальный запуск

1. Создайте локальный `main/config.py` с `token_ms`, `token_tg` и списком `users`, либо задайте соответствующие переменные окружения `MOYSKLAD_TOKEN`, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_USER_IDS`.
2. Установите зависимости командой `pip install -r requirements-dev.txt`.
3. Запустите `main/bot.py` из PyCharm. Для просмотра интерфейса без Telegram откройте `http://127.0.0.1:8000/?demo=1`. Для проверки живых данных откройте Mini App из Telegram с разрешённого аккаунта.

`MINIAPP_LOCAL_DEV=1` ограничивает веб-сервер локальным компьютером; API всё равно требует действительную подпись Telegram. После локальной проверки остановите процесс; не переносите `MINIAPP_LOCAL_DEV=1` на сервер.

## Размещение на сервере

Хостинг должен поддерживать Docker, постоянный фоновый процесс, входящие HTTP-запросы и постоянный диск. Платформа должна выдавать Mini App публичный HTTPS-адрес и проксировать запросы на порт из `PORT`. Используйте один экземпляр приложения: бот работает через long polling, а заказы хранятся в SQLite.

1. Соберите образ из корня проекта: `docker build -t paradise-bot .`.
2. Задайте `TELEGRAM_BOT_TOKEN`, `MOYSKLAD_TOKEN`, `TELEGRAM_USER_IDS`, публичный `MINIAPP_URL` и `CUSTOMER_ORDERS_DB` в настройках хостинга.
3. Подключите постоянный диск и направьте `CUSTOMER_ORDERS_DB` на него, например `/data/customer_orders.sqlite3`. Фотографии заказов сохраняются рядом с базой в каталоге `customer_order_photos`.
4. Оставьте `MINIAPP_LOCAL_DEV` незаданной или пустой. Не копируйте `main/config.py` в образ и не добавляйте `.env` в Git. На VPS допустим защищённый файл окружения, переданный контейнеру через `--env-file`.
5. После запуска откройте настройки бота в BotFather и подключите публичный HTTPS-адрес как Mini App. Либо используйте inline-кнопку, которую бот отправляет, когда задан `MINIAPP_URL`.
6. Откройте приложение внутри Telegram и проверьте остатки, закупки и создание/удаление заказов покупателей.

Docker-образ задаёт `/data/customer_orders.sqlite3` как путь по умолчанию и объявляет `/data` томом. На хостинге всё равно нужно подключить постоянный диск к этому пути или указать путь своего диска в `CUSTOMER_ORDERS_DB`: обычная файловая система контейнера может очищаться при пересборке.

## Зависимости

- `requirements.txt` — зависимости приложения для сервера.
- `requirements-dev.txt` — зависимости приложения и инструменты разработки/тестов.

## Проверенная версия и тестовый бот

Рабочая версия использует Python 3.11 и aiogram 3.31.0. Для ABC-XYZ отдельные запросы к МоемуСкладу ожидают ответ до 60 секунд и дважды повторяются при таймауте чтения; остальные запросы используют обычный лимит.

Локальные тесты запускаются одной командой из корня проекта. Фиктивные значения не дают тестам читать локальный `main/config.py`:

```bash
TELEGRAM_BOT_TOKEN=123456:TESTTOKEN MOYSKLAD_TOKEN=offline-dummy TELEGRAM_USER_IDS=101 .venv/bin/python -m pytest -q tests
```

На VPS основной и тестовый боты запускаются отдельными контейнерами с разными токенами Telegram, адресами Mini App и каталогами данных. Тестовый контейнер запускается с `PARADISE_OFFLINE_TEST_MODE=1` и без `MOYSKLAD_TOKEN`: остатки, продажи, рекомендации закупки и ABC-XYZ используют синтетические товары с пометкой «ТЕСТ». В этом режиме прямой запрос к API МоегоСклада заблокирован в коде; наличие токена МоегоСклада не даст приложению запуститься. Тестовые заказы хранятся в отдельном пустом томе. Не запускайте одновременно два контейнера с одним токеном Telegram.

Перед обновлением основного контейнера сохраняйте его образ, а SQLite-базу и каталог фотографий копируйте вместе при остановленном контейнере. После обновления проверьте `/start`, Mini App, остатки и создание/удаление тестового заказа. Тесты миграции находятся в `tests/test_bot_migration.py`; формирование PDF проверяется командой `node tests/test_purchase_pdf.js`.

## Важная особенность данных

Черновик закупки хранится в браузере пользователя. Заказы покупателей хранятся на сервере в SQLite и используют локальную папку для фотографий. При миграции или смене хостинга перенесите базу и папку фотографий; не размещайте их в эфемерном слое контейнера.
